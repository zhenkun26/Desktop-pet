## PR-DP-001：Tauri 流式事件丢失，界面卡在思考中

- **现象与影响**：历史记录已出现完整回复，但 delta/done 未到聊天窗口，界面长期停在思考气泡；重开或切换会话后可见回复。
- **复现条件**：旧 Tauri 版本；流式生成运行在 spawn 任务；依赖 `app.emit` 的事件到达窗口。
- **调查过程**：对比数据库与 UI 状态；检查单通道广播、双通道投递、seq 去重、看门狗和过期事件拦截的连续演进。
- **失败方案**：双通道冗余、seq 集合、看门狗和过期事件拦截都只能缓解传输不可靠性，并且引入重复、乱序或单位错误。
- **最终根因**：完成状态与增量事件共享了不可靠的运行时传输边界；旧 UI 又把事件当作完成事实。
- **最终修复**：迁移 Electron；assistant 前置落库；invoke 挂到终结；事件改为定向投递。见 [`refactor-tauri-to-electron`](../openspec/changes/refactor-tauri-to-electron/)。
- **验证结果**：当前服务测试覆盖成功/取消/错误，类型检查、构建和 81 项测试通过；历史现场无独立日志，GUI 丢事件验收仍待补。
- **防止复发**：数据库保存最终状态；事件只做增量优化；所有终结路径幂等。
- **个人反思**：连续修补表象会增加状态空间；应先定义完成事实和可恢复边界。

## PR-DP-002：历史消息重渲染摧毁流式气泡

- **现象与影响**：思考气泡短暂出现后消失，流式文本不再更新；数据库已有结果，用户认为对话卡死。
- **复现条件**：生成期间触发历史消息重渲染；流式气泡仍挂在会被整体 `innerHTML` 清空的消息区。
- **调查过程**：确认数据库已有 assistant 行；检查旧版 `renderMessages()` 的清空范围；比较 `state.messages` 与独立气泡生命周期；定位错误类型气泡重建 guard。
- **失败方案**：`isConnected` 检测、自愈重建、渲染后 guard；这些方案都没有解决共享 DOM 所有权问题。
- **最终根因**：历史列表是可重建状态，流式气泡是瞬态节点，二者共用清空边界。
- **最终修复**：增加 `#message-list`/`#stream-container`；历史渲染只清单；统一 `finalizeStream()` 清理和重载消息；移除脆弱 guard。
- **验证结果**：当前代码结构与 OpenSpec 一致，自动化检查全绿；OpenSpec 5.1–5.5 手动 GUI 验证仍未勾选，不能宣称实机闭环已完成。
- **防止复发**：明确 DOM 所有权；补浏览器级测试覆盖重渲染、切会话、停止和 invoke fallback。
- **个人反思**：状态变量不能替代真实节点生命周期；“可自愈”不应成为边界设计缺陷的长期掩盖层。

## PR-DP-004：better-sqlite3/node-gyp 构建失败

- **现象与影响**：原生数据库依赖在本机无法完成 node-gyp 构建，阻塞安装/打包路径。
- **调查过程与根因**：重构 tasks 3.1 记录 Python 3.13 移除 distutils 导致构建失败；当前实现改用 Electron 内置 `node:sqlite`。
- **最终修复与验证**：去除原生依赖，当前构建和数据库测试通过；原始 node-gyp 错误输出未保存在仓库。
- **待补**：若要升级为 A 级复盘，应补失败命令、完整 stderr、Node/Python 版本和迁移前后安装时间对比。
